# Plan to Push Source Code to GitHub on New Branch 'desktop'

## Objective
Push only source code files (excluding large binary files, data files, and dependency directories) to a new branch named 'desktop' on GitHub.

## Steps

1. **Update the local main branch** (if necessary) to ensure we are starting from the latest.
   - However, note that the current branch is behind 'public/main' by 1 commit. We may need to pull first.
   - But the user did not specify to update the main branch. We can decide to create the new branch from the current state of main.

2. **Create and switch to the new branch 'desktop'**.
   - Command: `git checkout -b desktop`

3. **Identify and stage source code files**.
   - We will use a PowerShell script to find all files with source code extensions, excluding certain directories.
   - Source code extensions include: .js, .ts, .jsx, .tsx, .html, .htm, .css, .scss, .sass, .less, .py, .java, .cpp, .c, .h, .cs, .go, .rs, .php, .rb, .swift, .kt, .kts, .m, .mm, .pl, .sh, .bash, .zsh, .fish, .sql, .graphql, .prisma, .dart, .lua, .vim, .viml, .elm, .ex, .exs, .erl, .hrl, .ml, .mli, .fs, .fsi, .fsx, .fsscript, .v, .vhd, .vhdl, .sv, .svh, .ada, .ads, .adb, .lisp, .cl, .clj, .cljs, .edn, .r, .R, .matlab, .scala, .sbt, .gradle, .groovy, .md, .markdown, .mjs
   - Exclude directories: .git, .kilo, .vite, resources, screenshot, cline, prompt, node_modules, __pycache__, bin, obj, and any other non-source directories.
   - The script will output the list of files to be staged.

4. **Stage the identified source code files**.
   - Use `git add` on the list of files obtained in step 3.

5. **Commit the staged files**.
   - Use `git commit -m "Add source code files to desktop branch"` or a more descriptive message.

6. **Push the new branch to the remote repository**.
   - Use `git push -u origin desktop`

## Notes
- We are not including large files (like binaries, media, etc.) by only selecting source code extensions.
- We are excluding known non-source directories to avoid including build artifacts, dependencies, etc.
- If there are any large source code files (which is unusual), they would still be included. However, the user's request to exclude large files is interpreted as excluding non-source large files.

## Verification
- After pushing, we can verify on GitHub that the branch 'desktop' contains only the source code files and the expected changes.

## Implementation
The following PowerShell script can be used to generate the list of files to stage:

```powershell
$extensions = @('.js', '.ts', '.jsx', '.tsx', '.html', '.htm', '.css', '.scss', '.sass', '.less', '.py', '.java', '.cpp', '.c', '.h', '.cs', '.go', '.rs', '.php', '.rb', '.swift', '.kt', '.kts', '.m', '.mm', '.pl', '.sh', '.bash', '.zsh', '.fish', '.sql', '.graphql', '.prisma', '.dart', '.lua', '.vim', '.viml', '.elm', '.ex', '.exs', '.erl', '.hrl', '.ml', '.mli', '.fs', '.fsi', '.fsx', '.fsscript', '.v', '.vhd', '.vhdl', '.sv', '.svh', '.ada', '.ads', '.adb', '.lisp', '.cl', '.clj', '.cljs', '.edn', '.r', '.R', '.matlab', '.scala', '.sbt', '.gradle', '.groovy', '.md', '.markdown', '.mjs')
$excludeDirs = @('.git', '.kilo', '.vite', 'resources', 'screenshot', 'cline', 'prompt', 'node_modules', '__pycache__', 'bin', 'obj')

Get-ChildItem -Path . -Recurse -File | 
  Where-Object {
      $fullPath = $_.FullName
      # Check if the file is in any excluded directory
      $excluded = $false
      foreach ($dir in $excludeDirs) {
          if ($fullPath -like "*\$dir\*") {
              $excluded = $true
              break
          }
      }
      if (-not $excluded) {
          # Check extension
          $ext = $_.Extension
          if ($extensions -contains $ext) {
              return $true
          }
      }
      return $false
  } | 
  Select-Object -ExpandProperty FullName
```

This script outputs the full paths of the files to be staged.
