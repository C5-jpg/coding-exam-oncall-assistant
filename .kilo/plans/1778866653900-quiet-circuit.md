## 三、架构分析（源码逐模块）

### 3.1 配置与常量（第1-218行）

| 组件 | 行号 | 功能 |

| `STOPWORDS` | 198-218 | 中英文停用词（"了"、"的"、"怎么"、"处理"等） |

### 3.2 文本处理工具函数（第221-269行）

| 函数 | 功能 |
|------|------|
| `compact_spaces()` | 合并连续空白 |
| `normalize()` | HTML实体解码 + 小写化 + 合并空白 |
| `chinese_ngrams()` | 中文字符 2/3/4-gram 生成（替代中文分词器） |
| `tokenize()` | 综合分词：英文单词提取 + 中文 n-gram + 领域短语匹配 |
| `split_query_terms()` | 查询拆分为去重的术语列表 |

### 3.3 `VisibleTextExtractor`（第272-324行）

- 继承 `HTMLParser`，提取可见文本
- **忽略** `<script>`、`<style>`、`<noscript>`、`<template>`、`<svg>`、`<canvas>`
- 分离 `<title>` 和 `<body>` 文本
- 在块级元素（`<p>`、`<br>`、`<li>`、`<h1>`-`<h4>` 等）前后插入空格

### 3.4 `Document` / `SearchResult` 数据类（第327-357行）

- `Document`：id、title、html、text、source_path、token_counts、norm_text
- `SearchResult`：id、title、snippet、score + `to_dict()` 方法

### 3.5 `DocumentIndex` 搜索引擎（第360-514行）

| 方法 | 阶段 | 功能 |
|------|------|------|
| `load_data_dir()` | 启动 | 扫描 data/ 下所有 *.html，解析并建索引 |
| `add_document()` | Phase1 | 添加文档，触发 IDF 重建 |
| `rebuild()` | 通用 | 计算全局 IDF：`log((1+N)/(1+df)) + 1` |

| `semantic_search()` | Phase2 | 规则扩展查询 + TF-IDF + per-doc boost |
| `expand_query()` | Phase2 | 匹配 SEMANTIC_RULES 获取扩展词和 boost |
| `make_snippet()` | 通用 | 以最佳匹配位置为中心，截取 ±86 字符的摘要 |

## 六、技术亮点

1. **零依赖**：纯 Python 标准库实现，无需 pip install，可在任何 Python 3.10+ 环境直接运行
2. **中文 n-gram 分词**：不依赖 jieba 等分词库，使用 2/3/4-gram 实现中文子串匹配
3. **领域短语匹配**：40+ 个领域短语作为分词补充，提升专业术语的检索精度
4. **HTML 容错解析**：`HTMLParser` 能处理未闭合标签、深层嵌套等畸形 HTML
5. **Script/Style 过滤**：正确忽略 `<script>`、`<style>` 等非可见内容，防止噪声污染索引
6. **HTML 实体解码**：`unescape()` 正确处理 `&#45;`、`&amp;`、`&comma;` 等各种实体
7. **语义规则引擎**：11 条手写规则覆盖主要查询场景，触发词 → 扩展词 + per-doc boost
8. **Agent 专用回答**：针对 5 种常见场景提供结构化的排障指南
9. **安全的 readFile**：路径遍历防护，禁止通配符和路径分隔符
10. **线程安全**：`ThreadingHTTPServer` 支持并发请求

## 七、潜在问题与观察

### 7.1 已知设计限制

| 项目 | 说明 | 严重程度 |
|------|------|----------|
| 语义搜索依赖手写规则 | 11 条规则覆盖有限，新领域需手动添加 | 低（demo 环境可接受） |
| Agent 回答为硬编码模板 | 5 种场景有专用回答，其他场景走通用提取 | 低（demo 环境可接受） |
| 无持久化 | 索引仅在内存中，重启需重建 | 低（demo 环境可接受） |
| 无认证/鉴权 | 所有 API 公开访问 | 低（demo 环境可接受） |
| 中文 n-gram 可能产生噪声 | 短 n-gram 可能匹配不相关文档 | 低（IDF 权重可缓解） |

### 7.2 代码质量观察

- **无注释要求**：代码符合"不添加注释"的要求
- **类型标注完整**：使用 `from __future__ import annotations` + 类型提示
- **数据类使用**：`@dataclass` 简洁定义数据结构
- **单文件设计**：便于提交和评审，但 1104 行偏长
